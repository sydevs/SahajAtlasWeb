# Cloudflare Pages serves this from the build output, like _redirects and _headers.
# NOTE it lands in BOTH: `pnpm build` copies public/ into dist/ (the `sahajatlas` app)
# and `pnpm ladle:build` copies it into build/ (the `sahajatlas-design` playground), so
# this one file is the policy for both projects. That is wanted — a component playground
# is no more a search surface than the app is — but it means the runbook at the bottom
# opens the playground too.
#
# ---------------------------------------------------------------------------------
# THE POLICY, and the one place it is written down (issue #106).
#
# Search is owned by WeMeditate and the other embedding sites. This deployment is the
# standalone build of an EMBEDDABLE widget: every canonical link and every share URL it
# emits already points at SahajCloud's `webUrl` — the WeMeditate surface — so a
# sahajatlas.* URL in a result page is a duplicate of somebody else's page, not a
# destination of its own. Hence: resist direct indexing.
#
# Three signals carry that, and they are NOT interchangeable:
#   - this file       — do not fetch.
#   - X-Robots-Tag    — do not index, on every URL (public/_headers).
#   - <meta robots>   — do not index, without depending on Cloudflare (index.html).
#
# THE INTERACTION THAT MATTERS. `Disallow` means "do not fetch", not "do not index" — so
# a compliant crawler that never fetches a page also never sees the `noindex` we serve on
# it. The two do not stack; the weaker signal hides the stronger. Residual risk, accepted
# deliberately: a URL linked from an external page can still be listed URL-only, with no
# title or snippet.
#
# RUNBOOK. If sahajatlas.* is ever FOUND in an index, relax this file rather than
# tightening it — swap `Disallow: /` for `Allow: /` so the crawler can fetch the page,
# read the noindex and drop the entry, then restore this once it is gone. Remember that
# doing so opens sahajatlas-design.pages.dev for the same window (see the note above).
# ---------------------------------------------------------------------------------
User-agent: *
Disallow: /

# Link-preview scrapers, allowed because they are not search engines and none of them
# feeds an index — so allowing them costs nothing against the policy above.
#
# WHAT THIS ACTUALLY BUYS, stated honestly: this build is client-rendered and has no
# prerender step, so the og:* tags and the schema.org JSON-LD are injected by
# react-helmet-async at RUNTIME and none of these bots executes JavaScript. What they
# can see in the served HTML is `<title>Sahaj Atlas</title>` and nothing else. So the
# group is the difference between a generic-titled card and a bare link — NOT a rich
# per-event unfurl, which a sahajatlas.* URL cannot produce today with or without this
# file. Rich unfurls come from the canonical `webUrl` on WeMeditate, which is what
# ShareView hands out whenever the event has one; the fallback
# (`event.webUrl ?? window.location.href`, for an unpublished or gated event) is the
# case that lands here. If prerendering is ever added, this group is what makes it
# visible; see .claude/reports/RELEASE_READINESS.md §6.
#
# The list tracks `PlatformKey` in src/lib/share/platforms.ts — the targets the share
# grid actually offers — plus the places a copy-pasted URL commonly lands. Keep the two
# in step. `weibo` is a PlatformKey with no allowance here: its crawler's product token
# could not be confirmed, and guessing one would be a rule that silently matches nothing.
#
# NOT ALL OF THEM OBEY THIS FILE, and that is fine — an allowance is a permission, not a
# request. Slack states outright that it does not process robots.txt
# (https://api.slack.com/robots), and Meta documents that facebookexternalhit may bypass
# it for integrity checks. Their lines are kept because they cost nothing and both
# vendors have changed this before. The ones where the allowance is load-bearing are the
# documented robots.txt-honouring previewers: redditbot, Twitterbot, LinkedInBot.
#
# One group, many tokens: the format applies a group's rules to every User-agent line in
# it, and a crawler that matches a specific group never falls back to `*`. Slack appears
# three times because group selection matches the whole product token rather than a
# prefix of it, and its unfurl, its legacy and its image fetchers are separate tokens.
User-agent: facebookexternalhit
User-agent: Twitterbot
User-agent: LinkedInBot
User-agent: redditbot
User-agent: WhatsApp
User-agent: TelegramBot
User-agent: Discordbot
User-agent: Slackbot
User-agent: Slackbot-LinkExpanding
User-agent: Slack-ImgProxy
User-agent: vkShare
User-agent: OdklBot
User-agent: Viber
User-agent: line-poker
Allow: /
